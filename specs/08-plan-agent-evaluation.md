## Plan Agent 深度洞察与测评执行计划

### Summary

面向 OpenCode 的 **plan agent**（专业性/规划能力），先完成实现层面的深度洞察，再产出可复用的测评集与评估方法，并给出可执行的落地计划。

---

### Goals

- 梳理 plan agent 的现有实现机制、权限边界与工作流约束
- 形成覆盖多类型任务的测评集与评分标准
- 给出分阶段、可跟踪的执行计划与产出物

---

### Non-goals

- 不改动 plan agent 行为或权限逻辑
- 不新增模型或运行时组件

---

### 深度洞察（基于现有实现）

1. **权限边界与模式定位**
   - plan agent 作为 **primary agent**，默认仅允许编辑 plan 文件，禁止编辑其他文件。
   - 关键权限逻辑位于 `packages/opencode/src/agent/agent.ts`：
     - `edit` 默认 `deny`，仅允许 `.opencode/plans/*.md` 与全局数据目录 `plans/*.md`。
     - `plan_exit` 允许，`plan_enter` 默认拒绝（由 build 触发）。

2. **Plan 进入/退出机制**
   - `packages/opencode/src/tool/plan.ts` 中定义 `plan_enter` / `plan_exit`：
     - `plan_enter`：由 build 提示用户切换到 plan，并生成合成消息。
     - `plan_exit`：提示用户确认切换回 build 执行。

3. **Plan 文件位置规则**
   - `packages/opencode/src/session/index.ts` 中定义 `Session.plan`：
     - 有 VCS 项目时：`<worktree>/.opencode/plans/{time}-{slug}.md`
     - 无 VCS 项目时：`<global data>/plans/{time}-{slug}.md`

4. **Plan 模式提示与工作流**
   - `packages/opencode/src/session/prompt.ts` 中包含 plan 模式系统提示（包含阶段化流程）。
   - 强调“只读探索 → 设计 → 审核 → 输出计划 → plan_exit”闭环。

5. **官方文档定位**
   - `packages/web/src/content/docs/agents.mdx` 描述 plan agent 的限制与用途。
   - `packages/web/src/content/docs/modes.mdx` 补充 plan 模式限制。

### 测评框架

#### 评估维度（建议权重）

1. **问题理解与澄清（20%）**
   - 是否识别需求歧义并提出关键问题
2. **方案完整性（25%）**
   - 覆盖关键步骤、依赖、边界条件
3. **实现可执行性（20%）**
   - 是否包含明确文件路径、修改点、验证步骤
4. **风险识别与权衡（20%）**
   - 是否识别安全/性能/可维护性风险并给出缓解
5. **结构与表达（15%）**
   - 计划结构清晰、可扫描、步骤顺序合理

#### 评分规则

- 每维度 0-5 分，综合得分加权。
- 至少两位评审交叉评分，分歧 >1 分需复审。

---

### 测评集设计（覆盖任务类型）

> 每条任务包含：**任务描述 / 预期产出重点 / 关键风险点**

1. **单文件修复**
   - 例：修复一个函数的边界条件错误
   - 重点：定位文件与修改点，说明验证步骤
2. **多文件特性新增**
   - 例：新增一个 CLI 子命令并更新文档
   - 重点：列出涉及文件、配置/命令注册流程
3. **配置/权限类改动**
   - 例：新增一个受限工具权限规则
   - 重点：明确规则合并顺序与安全影响
4. **性能优化任务**
   - 例：优化大型列表渲染或缓存策略
   - 重点：基准指标与回归风险
5. **安全敏感变更**
   - 例：处理凭据泄露或输入校验
   - 重点：威胁模型与验证策略
6. **文档/流程改动**
   - 例：新增使用指南并更新导航
   - 重点：信息结构一致性与可发现性
7. **模糊需求澄清**
   - 例：用户仅描述“性能慢，需要优化”
   - 重点：提出澄清问题并给出多路径方案

#### 样例测评条目（模板）

```
任务：<一句话需求>
上下文：<相关系统/限制>
预期重点：<必须覆盖的计划要点>
风险点：<应识别的风险>
```

### 执行计划（详细步骤）

1. **准备阶段（第 1 天）**
   - 审核现有 plan agent 实现与文档
   - 定义评估维度与评分表
2. **测评集构建（第 2-3 天）**
   - 生成 15-20 条任务样本，覆盖 7 类任务
   - 为每条任务补充预期重点与风险点
3. **试测与校准（第 4 天）**
   - 选 3-5 条任务进行试评
   - 校准评分尺度与评估一致性
4. **正式评测（第 5-7 天）**
   - 多评审并行评分
   - 汇总得分、维度雷达图与代表性案例
5. **总结与输出（第 8 天）**
   - 输出评测报告、改进建议与后续迭代计划
